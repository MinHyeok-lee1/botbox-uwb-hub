# 컨트롤 보드 개발 요청 — BotBox+ PDoA+TWR 단일 앵커 추종 실차 시험

2026-11-20 · 작성 BBX · 근거 지시 t42u, t43u · 인터페이스 기준: `BBX_PDoA_TestCAN_0x244_v0.2_20261120.md` (같은 폴더)
표기: **[요청]** = 컨트롤 보드 담당 개발자에게 구현을 요청하는 항목 · **[참고]** = 판단·설계를 위한 정보

## 1. 수신·디코딩
- **[요청]** CAN ID **0x244**(Classic 2.0B, 표준 11비트, DLC 8, **500 kbps**)를 수신해 v0.2 §2 배치대로 디코딩한다. Little Endian.
- **[요청]** 필터는 **0x244 정확 일치**로 건다. 출고 `321ccc1`의 UWB 수신은 하위 니블(1/2/3)로 좌/우/후 슬롯을 나누므로(`uwb_manager.cpp:855-866`), 0x244가 기존 3앵커 슬롯 처리로 들어가지 않게 한다. 0x244의 니블 4는 슬롯에 걸리지 않는다.
- **[참고]** 기반 펌웨어: 출고 `321ccc1` CAN3 = 250 kbps, kaist-vlm `aaa6ffc` CAN3 = 500 kbps(0x240 수신부 있음). 선택은 담당 개발자가 한다.

## 2. 신선도 처리
- **[요청]** `seq`와 `rf_age`로 신선도를 판단한다. seq 차이 0은 같은 결과의 재송신(오류 아님), 2–127은 누락, 128–255는 역순이다(v0.2 §6).
- **[요청]** 수신 타임아웃은 자체 타이머로 둔다.
- **[참고]** 연구용 참고값: 0x244 미수신 200 ms, RF 관측 공백 250 ms, HELD 상한 160 ms, RESTARTED 구간 약 1 s. 최종값은 담당 개발자가 정한다.
- **[참고]** `src` 구분: HELD = 이전 방향을 제한된 시간 동안 유지, REFERENCE = 현재 관측 군집 + 이전 판단(v0.2 §4).

## 3. 제어 정책 (담당 개발자 소관)
- **[요청]** 조향·감속·정지·재출발 정책은 담당 개발자가 설계·구현한다. BBX는 추종 알고리즘이나 안전 제어를 구현하지 않는다.
- **[요청]** 기존 3앵커 추종과 기존 안전 기능(비상정지·초음파·범퍼), **최종 주행 권한(컨트롤 보드)** 을 유지한다.
- **[요청] 본부장 안전 원칙**: `LAT_VALID=0`일 때 거리만으로 계속 전진하지 않는다. 전후방 판단은 지원되지 않는다(태그가 뒤에 있어도 같은 값).
- **[참고]** 실차 구동 시험의 승인 범위는 본부장이 정한다. 이 문서는 구동 승인을 뜻하지 않는다.

## 4. 시험 기록
- **[요청]** 수신한 0x244 원본 8바이트를 수신 시각과 함께 로그로 남긴다(시험 분석용). 가능하면 컨트롤 보드의 제어 출력(조향·속도 지령)도 같은 시각축으로 남긴다.

## 5. 전제 조건 (컨트롤 보드 범위 밖)
- **[참고]** HUB 0x244 송신 구현 — 아직 없음(현재 0x240/0x241만).
- **[참고]** HUB 출력 포트 Classic 500 kbps 설정 — 현재 FD+BRS 모드 500k.
- **[참고]** 위상 부호(+ = LEFT) 실차 확인 — 현재 책상 시험 기준.
- **[참고]** LAT_VALID는 알고리즘 조건일 뿐 물리적 좌우 검증은 아니다. 25 Hz 실제 송수신과 3앵커 동시 레인징 성능은 미측정이다.
