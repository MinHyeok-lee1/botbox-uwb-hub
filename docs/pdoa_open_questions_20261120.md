# PDoA 0x244 — 열린 질문 모음 (2026-11-20)

아직 답을 받지 못한 질문과 결정 사항을 이 파일 한 곳에서만 관리합니다. 답을 받으면 해당 항목을 지우고, 내용은 관련 문서(질의·회신 기록, CLAUDE.md)에 반영합니다.

## UWB 팀

| # | 질문 | 왜 필요한가 | 지금 허브 동작 |
|---|---|---|---|
| U1 | Core가 방향을 실제로 지지한 표본의 tick(또는 SN)을 결과 필드로 내줄 수 있나요? | 0x244 rf_age는 "결과를 지지한 실제 RF 관측" 기준인데, 공개 결과에는 그 시각이 없음 | 마지막으로 수용한 관측 시각 기준. 그 관측이 방향을 지지하지 않으면 rf_age가 최대 Core 창 길이만큼 짧게 나올 수 있음 |
| U2 | 재부팅 보조 감지 기준(OBS 1 s 무수신 뒤 복귀, 이어지는 역행 SN 3개 연속, 재시작 뒤에는 새 CAL을 받아야 좌우 판정 사용)에 이견이 있나요? | boot_id 충돌 대비. 기준값은 실차 결과로 조정하기로 함 | 위 기준으로 구현됨 |

## BBX (컨트롤 보드 담당 포함)

| # | 질문·요청 | 왜 필요한가 |
|---|---|---|
| B1 | v0.2 §8 "Classic 500k로 설정해야 함 [미구현]"을 "버스상 classic 보장(허브가 CAN2에서 FD 프레임 차단)"으로 고쳐 주세요. | 허브는 FDCAN 설정을 FD_BRS로 두기로 결정 |
| B2 | 이번 시험(UWB_V3_ONLY)에서는 src=HELD가 나오지 않는다는 점을 §4·§6·§7에 적어 주세요. | UWB 팀 확인 사항 |
| B3 | seq 재기준 규칙: "수신 측은 자체 수신 타임아웃이 지나거나 RESTARTED=1을 받으면 seq 비교를 버리고 다음 프레임을 새 기준으로 삼는다"를 컨트롤 보드 담당과 합의해 주세요. | 결과가 128개(약 5.1 s) 넘게 빠지면 정상 프레임이 "역순"으로 해석됨 |
| B4 | 해석 확인: (1) 새 관측 없이 내용이 바뀌어도(태그 상실 등) seq +1, (2) quality는 Core 점수 기준, (3) RESTARTED 해제는 seq를 올리지 않음, (4) rf_age는 LAT_VALID=1이면 좌우를 지지한 관측, 아니면 거리 관측 기준 | 허브는 이렇게 구현됨 |
| B5 | IF-5 임시 동작 승인: PDOA_ONLY 모드에서 하트비트 상태는 0x244 결과 기준(거리·좌우 모두 유효하면 RUN, 아니면 READY, 결과가 멈추면 DEGRADED), CFG 출력 주기(0x0001) 응답은 25 Hz | IF-5 명세(v0.11)는 0x240 기준이라 시험 기간 임시 동작 |
| B6 | rf_age 한계 확인: CAN 전송 지연(약 0.25 ms)은 포함하지 않고, 송신 대기 중 최대 20 ms 작게 나올 수 있으며, U1이 해결되기 전까지는 Core 창 길이만큼 짧게 나올 수 있음 | 컨트롤 보드의 신선도 기준값을 정할 때 고려 |
